# Database qualification

The store's ledger is one generated baseline (`module/services/store/migrations/`,
regenerated by `module/services/store/tools/generate_baseline.py`, declared by
`module/services/store/baseline.provenance.json`). This qualification installs it on
disposable local PostgreSQL 16 containers with networking disabled — never through a
DSN from the environment, never against managed infrastructure. Docker must have
the exact image in `run.py` cached.

Run the source checks and the real database suite:

```sh
python3 -m unittest discover -s qualification/managed-database -p 'test_*.py'
python3 qualification/managed-database/ci.py /tmp/database-qualification.json
```

`ci.py` verifies the published migration primitive module checksum and builds its
pinned golang-migrate CLI for Linux amd64. `run.py --migrate /absolute/migrate
--output /tmp/result.json` accepts an already qualified binary. The suite installs
the ledger twice — as a superuser and as a NOSUPERUSER/NOBYPASSRLS/CREATEROLE
principal — and requires one schema, one authority catalog and one seed catalog
from both; proves a replay changes nothing; exercises every runtime role boundary,
request-scope guard and revocation; and checks that the baseline refuses a
non-empty database, that a failed or interrupted install leaves nothing behind but a
dirty ledger, and that a down is refused before it removes anything. Disposable
superuser sessions only provision fixtures and perform independent observations.

To additionally qualify the supported managed-bootstrap/access reconciler, stage
the ledger with `stage.py --template-spec … --output …` and package it with the
reviewed schema-plan tool. The local template must name database `users`, groups
`example_ro`/`example_rw`, principals `example_reader`/`example_writer`, and all
five canonical application roles in `read-write-roles`; the owner is
`example_migrator`. External reader/writer fixture logins are LOGIN INHERIT before
reconciliation; access groups and application roles remain NOLOGIN/NOINHERIT.
PostgreSQL 16 stores inheritance on each membership edge: changing a login's
INHERIT attribute later does not repair an existing non-inheriting edge. Pass
`--package /absolute/package` to `run.py`. Packages contain the published
managed-bootstrap and migrate binaries, immutable `bootstrap/plan.json`/sources,
and `binding.json`. The suite runs bootstrap as OS UID 65532, checks
access-committed receipts and replay, and verifies that runtime logins cannot
assume the migration owner.

None of this claims managed-provider, IAM, proxy or hosted execution
qualification. Final evidence must pin a clean commit.
